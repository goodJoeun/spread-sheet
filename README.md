# spread-sheet

여러 사람이 동시에 편집하고, AI의 도움도 받을 수 있는 웹 스프레드시트입니다.

## 실행 방법

Node.js 20 이상이 필요합니다.

```bash
npm install
cp .env.example .env.local   # ANTHROPIC_API_KEY 입력
npm run dev
```

브라우저에서 http://localhost:3000 을 엽니다. 같은 주소를 탭 여러 개로 열면, 탭마다 서로 다른 사용자가 됩니다.

## 스크립트

## 공동 편집

### 다른 사용자가 무엇을 하고 있는지 보입니다

다른 사용자의 선택 범위와 커서는 그 사람의 색 테두리와 이름표로 보입니다. 참여자 목록에는 "B2 입력 중", "A1:C3 보는 중" 같은 상태가 나옵니다.

### 입력 중인 값도 바로 보입니다

다른 사용자가 셀에 입력하면, 확정하기 전이라도 그 셀에 글자가 실시간으로 나타납니다. 이름표에는 "입력 중"이 붙습니다. 한글을 조합하는 중인 글자, F2나 더블클릭으로 고치는 중인 기존 값도 똑같이 보입니다.

입력 중인 값은 문서에 쓰지 않습니다. 커서와 같은 경로(awareness)로만 보냅니다. 그래서 확정하기 전까지는 저장되지 않고, 실행 취소 기록에도 남지 않습니다. 입력하던 사람이 Esc로 취소하면 다른 화면에서도 원래 값으로 돌아갑니다.

### 같은 셀을 동시에 고치면, 나중에 확정한 값이 남습니다

두 사람의 입력을 글자 단위로 섞지 않습니다. 셀 값은 "100"과 "200"이 섞이면 아무 의미 없는 값이 되기 때문입니다. Google Sheets도 같은 방식을 씁니다.

대신 같은 셀을 동시에 입력하면 편집칸 위에 "○○님도 이 셀을 입력 중이에요"를 띄워서, 서로 알아챌 수 있게 했습니다.

셀 값은 셀마다 객체를 따로 두지 않고 "B2" 같은 평평한(flat) 키로 저장합니다. 빈 셀에 두 사람이 동시에 처음 입력해도 두 변경이 모두 남게 하기 위해서입니다.

### 탭을 닫으면 바로 사라집니다

탭이 닫히면 Web Locks로 즉시 알아챕니다. 그 사용자의 커서, 입력 중인 값, AI 편집 표시가 다른 화면에서 바로 사라집니다.

## 공동 편집과 AI가 만나는 지점

### 1. AI가 결과를 만드는 동안 누가 그 셀을 고치면 어떻게 될까요?

AI에 편집을 요청하면 그 순간의 셀 값(이하 **요청 때 값**)을 함께 보냅니다. 그런데 AI가 결과를 만드는 사이에 다른 사용자가 같은 셀을 고칠 수 있습니다. 이때 AI 결과가 사람의 입력을 몰래 덮어쓰면 안 됩니다. 그래서 아래처럼 처리합니다.

**셀 잠금을 끈 경우 (기본)**

- AI 생성은 멈추지 않고 계속 진행합니다.
- 미리보기는 요청 때 값이 아니라, 항상 **현재 값**과 비교해서 보여 줍니다.
- 요청 때 값과 현재 값이 달라진 셀은 **충돌**로 표시합니다.
  - 시트에서는 현재 값을 가리지 않도록 주황 테두리만 두릅니다.
  - AI 패널에서는 "요청 때 값 → 현재 값"과 AI 제안 값을 나란히 보여 줍니다.
- 충돌한 셀은 기본으로 **적용하지 않고 건너뜁니다.**
  - 필요하면 셀마다, 또는 한 번에 덮어쓰기를 고를 수 있습니다.
  - **지금 값으로 다시 요청**을 누르면, 같은 요청을 최신 시트 기준으로 다시 보냅니다.
- 셀을 지운 것도 "빈칸으로 바뀐 것"으로 보고 같은 규칙을 따릅니다. 행·열 삽입 기능이 없어서 셀 주소가 밀리는 문제는 없습니다.
- AI 결과를 적용할 때 내가 입력 중이던 값이 있으면, 먼저 확정한 뒤 같은 규칙으로 판단합니다.
- 다른 사용자가 **입력 중인 값**은 화면에 보이더라도 충돌로 보지 않습니다. 아직 확정되지 않은 값이기 때문입니다.
  - 그 사용자가 내 적용보다 먼저 확정하면, 충돌로 표시되어 건너뜁니다.
  - 내 적용보다 나중에 확정하면, 그 값이 AI 값을 덮어씁니다.
  - 어느 쪽이든 사람이 입력한 값이 남습니다.

왜 사람의 입력을 우선했을까요? AI 결과는 다시 요청하면 또 만들 수 있지만, 사람이 입력한 값은 한 번 사라지면 되살리기 어렵기 때문입니다.

**셀 잠금을 켠 경우**

툴바의 **AI 편집 시 셀 잠금**을 켜고 요청하면, AI 생성부터 적용·버리기까지 다른 사용자는 요청한 범위의 셀을 바꿀 수 없습니다. 입력 시작, 지우기, 서식 변경이 모두 막힙니다. 그래서 위와 같은 충돌이 원칙적으로 생기지 않고, AI 제안을 그대로 적용할 수 있습니다.

다만 아래 경우에는 잠금을 켜도 셀 값이 바뀔 수 있습니다. 이때는 기본 동작과 같은 규칙으로 처리합니다.

- 잠기기 전부터 입력하던 값을 확정한 경우
- 잠금이 다른 탭에 전달되기 전, 아주 짧은 순간에 입력한 경우
- 다른 사용자가 잠기기 전에 한 자신의 편집을 실행 취소한 경우

잠긴 셀이 다른 사용자에게 어떻게 보이는지는 2번에서 이어서 설명합니다.

### 2. 한 사람이 AI 결과를 검토하는 동안, 다른 사용자에게는 무엇이 보일까요?

검토 중인 범위에는 검토하는 사람의 색 점선과 "○○ · AI 결과 검토 중" 이름표가 보입니다. 아직 생성 중이라면 "AI 편집 중"으로 보입니다. 참여자 목록에도 같은 상태가 나옵니다.

**AI의 제안 값은 보여 주지 않습니다**

확정되지 않은 값이 실제 데이터처럼 보이면 혼란스러울 것이라고 판단했습니다.

사람이 입력 중인 값은 보여 주는데, AI 제안은 왜 다르게 다룰까요? 사람의 입력은 그 사람의 커서 테두리와 "입력 중" 이름표 안에 한 칸씩 나타나서, 실제 값과 쉽게 구분됩니다. 반면 AI 제안은 범위 전체에 한꺼번에 깔려서 실제 데이터처럼 보이기 쉽습니다. 토큰이 올 때마다 모든 탭에 값을 보내야 하는 부담도 있습니다.

**기본으로는 막지 않고 알리기만 합니다 (soft lock)**

다른 사용자가 AI로 편집하거나 검토 중인 범위라도, 내가 편집하는 것은 막지 않습니다. 대신 입력을 시작하면 편집칸 위에 "○○님이 AI 결과 검토 중 · 입력한 값은 기본으로 유지돼요"를 띄웁니다.

- 기본을 하드 락(hard lock)으로 두지 않은 이유: 사람의 작업 흐름이 AI 때문에 끊기기 때문입니다.
- 확인 창으로 묻지 않는 이유: 확인 창이 편집칸의 포커스를 빼앗으면 한글 조합이 중간에 끊기기 때문입니다.

**셀 잠금을 켜면 막습니다 (hard lock)**

툴바의 **AI 편집 시 셀 잠금**을 켜고 요청하면, 결과를 적용하거나 버릴 때까지 요청한 범위를 다른 사용자가 바꿀 수 없습니다. 시트 전체로 요청했다면 시트 전체가 잠깁니다.

- 잠긴 셀에서 입력을 시작하거나, 지우거나, 서식을 바꾸려고 하면 막히고 "○○님이 AI 편집을 위해 잠근 셀이에요"가 뜹니다.
- 이름표와 참여자 목록에는 "· 잠금"이 붙습니다.
- 잠기기 전부터 입력하던 값은 확정할 수 있습니다. 이미 입력한 글자를 버리지 않기 위해서입니다. 그 셀은 1번 규칙대로 충돌로 표시됩니다.
- 잠금은 토글을 켠 뒤의 다음 요청부터 적용됩니다. 요청할 때 정해진 범위는 실행이 끝날 때까지 바뀌지 않습니다.

검토하던 탭이 닫히면 Web Locks로 즉시 알아채서 표시와 잠금이 함께 사라집니다. 그래서 탭이 비정상적으로 종료되어도 잠금이 남지 않습니다.

### 3. 두 사람이 겹치는 범위에 동시에 AI 편집을 요청하면 어떻게 될까요?

보내기 전에 요청창 위에 "○○님이 이 범위를 AI로 편집 중이에요"가 뜹니다. 그래도 요청은 막지 않습니다.

먼저 적용한 쪽의 변경은, 나중에 적용하는 쪽에게 1번 규칙대로 충돌로 표시되고 기본으로 건너뜁니다. 두 AI가 같은 값을 냈다면 충돌이 아닙니다.

잠금이 없으니 서로 기다리다 멈추는 일도 없습니다. 거의 동시에 눌러서 서로의 표시를 못 본 경우에도 같은 규칙으로 처리됩니다. 누가 먼저 봤는지에 결과가 좌우되지 않습니다.

셀 잠금을 쓸 때는 예외입니다. 다른 사람이 잠근 범위에는 요청할 수 없고, 다른 AI 편집과 겹치는 범위는 잠글 수 없습니다. 그래서 잠긴 범위에는 언제나 AI 실행이 하나뿐입니다.

## 아직 남은 한계

- 같은 셀을 두 사람이 동시에 확정하면, 먼저 확정한 값은 사라집니다. 서로 입력하는 모습과 안내는 보이지만, 막지는 않습니다.
- AI 결과를 적용하는 것과 거의 같은 순간(탭 사이에 메시지가 전달되는 짧은 시간)에 다른 탭에서 같은 셀을 고치면, CRDT 규칙에 따라 모든 탭이 두 값 중 하나로 똑같이 맞춰집니다. 이 짧은 틈까지 막으려면 서버가 순서를 정해 줘야 합니다.
- 셀 잠금도 탭 사이 메시지로 알리기 때문에, 잠금이 전달되기 전의 아주 짧은 순간에 한 입력은 막지 못합니다. 이 입력은 충돌로 처리됩니다.
- 셀 잠금은 실행 취소·다시 실행은 막지 않습니다. 잠기기 전에 그 셀에 한 편집을 되돌리면 값이 바뀌고, AI 결과에서 충돌로 표시됩니다.
- 검토 중인 제안은 그 탭에만 있습니다. 새로고침하면 사라져서 다시 요청해야 합니다.
