# spread-sheet

여러 탭에서 동시에 편집하고, AI의 도움을 받아 편집할 수 있는 웹 스프레드시트입니다.

> 개발 중입니다.

## 실행 방법

Node.js 20 이상이 필요합니다.

```bash
npm install
cp .env.example .env.local   # ANTHROPIC_API_KEY 입력
npm run dev
```

브라우저에서 http://localhost:3000 을 열고, 같은 주소를 탭 여러 개로 열면 각 탭이 서로 다른 참여자가 됩니다.

## 공동 편집과 AI가 만나는 지점

### 규칙 하나

> **AI에 요청한 순간의 셀 값을 기억해 두고, 그 뒤에 바뀐 셀은 "충돌"로 표시해 기본으로 건너뛴다.**

세 상황을 모두 이 규칙 하나로 처리합니다. 판단은 셀마다 세 값을 비교하는 순수 함수([`src/lib/ai/coedit.ts`](src/lib/ai/coedit.ts))가 합니다.

| 요청 때 값 → 지금 값 | AI 제안        | 상태      | 적용하면                             |
| -------------------- | -------------- | --------- | ------------------------------------ |
| 같음                 | 다름           | 적용      | AI 값으로 바뀜                       |
| 다름                 | 다름           | **충돌**  | 건너뜀(직접 덮어쓰기를 고를 수 있음) |
| 상관없음             | 지금 값과 같음 | 이미 같음 | 바꿀 것 없음                         |

- 충돌 여부는 저장하지 않고 화면을 그릴 때마다 지금 값으로 다시 계산합니다. 바꾼 사람이 원래 값으로 되돌리면 충돌도 저절로 풀립니다.
- 적용 버튼을 누른 순간에도 다시 판단합니다. 판단과 쓰기를 같은 동기 코드에서 하므로 그 사이에 다른 탭의 변경이 끼어들 수 없습니다.
- 덮어쓰기는 "고를 때 본 값"에 묶입니다. 고른 뒤에 또 바뀌면, 그 값은 확인하지 않았으므로 다시 건너뜁니다.

**이유:** 사람이 한 작업을 AI 결과가 몰래 덮어쓰면 안 됩니다. AI 결과는 다시 만들기 쉽지만 사람의 입력은 그렇지 않습니다. 같은 이유로, 적용한 AI 편집을 실행 취소할 때도 그 뒤에 다른 사람이 고친 셀은 되돌리지 않습니다(Yjs UndoManager의 기본 동작).

### 1. AI가 결과를 만드는 동안 다른 참여자가 대상 셀을 수정·삭제하면

- 생성은 멈추지 않고 계속합니다. 미리보기는 늘 **지금 값**과 비교해 보여 줍니다.
- 바뀐 셀은 미리보기에서 지금 값을 가리지 않고 주황 테두리만 두릅니다. 패널에는 "요청 때 값 → 지금 값"과 AI 제안을 함께 보여 줍니다.
- 기본은 건너뛰기입니다. 셀마다 또는 한 번에 덮어쓰기를 고를 수 있고, **지금 값으로 다시 요청**하면 같은 지시를 최신 시트로 다시 보냅니다.
- 삭제도 "빈칸으로 바뀐 것"이라 같은 규칙을 따릅니다. 행·열 삽입이 없어 주소가 밀리는 문제는 없습니다.
- 내가 입력 중이던 값도 적용 직전에 확정되어 같은 규칙으로 판단됩니다.

### 2. 한 사람이 AI 결과를 검토하는 동안 다른 참여자에게 보이는 것

- 그 범위에 검토하는 사람의 색 점선과 "○○ · AI 결과 검토 중"(생성 중이면 "AI 편집 중") 이름표가 보입니다. 참여자 목록에도 같은 상태가 나옵니다.
- **제안 값은 보이지 않습니다.** 확정되지 않은 값이 실제 데이터처럼 보이면 혼란스럽습니다. 또 토큰마다 모든 탭에 값을 보내게 되기 때문입니다. 참여자 정보에는 범위와 상태만 싣고, 상태나 범위가 바뀔 때만 보냅니다.
- 그 범위를 편집하는 것은 막지 않고 알리기만 합니다(soft lock). 입력하면 편집칸 위에 "○○님이 AI 결과 검토 중 · 입력한 값은 기본으로 유지돼요"가 뜹니다.
  - 하드 락을 쓰지 않는 이유: 탭이 비정상 종료되면 잠금이 남고, 사람의 작업 흐름이 AI 때문에 끊깁니다.
  - 확인 창으로 묻지 않는 이유: 편집칸의 포커스를 빼앗아 한글 조합이 중간에 끊깁니다.
- 검토하던 탭이 닫히면 Web Locks로 즉시 감지해 표시가 사라집니다.

### 3. 두 사람이 겹치는 범위에 동시에 AI 편집을 요청하면

- 보내기 전에 입력칸 위에 "○○님이 이 범위를 AI로 편집 중이에요"가 뜹니다. 그래도 요청은 막지 않습니다.
- 먼저 적용한 쪽의 변경은 나중 쪽에게 1번 규칙대로 충돌로 표시되고, 기본으로 건너뜁니다. 두 AI가 같은 값을 냈다면 충돌이 아닙니다.
- 잠금이 없으니 서로 기다리다 멈추는 일이 없습니다. 거의 동시에 눌러 서로의 표시를 못 본 경우에도 같은 규칙으로 처리되어, 누가 먼저 봤는지에 결과가 좌우되지 않습니다.

### 한계

- 적용과 거의 같은 순간(탭 간 전달 지연 안)에 다른 탭에서 같은 셀을 고치면, CRDT 규칙에 따라 두 값 중 하나로 모든 탭이 같게 수렴합니다. 이 짧은 틈까지 막으려면 서버가 순서를 정해 주어야 합니다.
- 검토 중인 제안은 그 탭에만 있습니다. 새로고침하면 사라지고 다시 요청해야 합니다.
