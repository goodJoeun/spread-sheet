# spread-sheet

여러 탭에서 동시에 편집하고, AI의 도움을 받아 편집할 수 있는 웹 스프레드시트입니다.

## 실행 방법

Node.js 20 이상이 필요합니다.

```bash
npm install
cp .env.example .env.local   # ANTHROPIC_API_KEY 입력
npm run dev
```

브라우저에서 http://localhost:3000 을 열고, 같은 주소를 탭 여러 개로 열면 각 탭이 서로 다른 참여자가 됩니다.

## 스크립트

| 명령                | 설명                 |
| ------------------- | -------------------- |
| `npm run dev`       | 개발 서버            |
| `npm run build`     | 프로덕션 빌드        |
| `npm run lint`      | ESLint               |
| `npm run typecheck` | TypeScript 타입 검사 |

## 공동 편집과 AI가 만나는 지점

### 1. AI가 결과를 만드는 동안 다른 참여자가 대상 셀을 수정·삭제하면

- 생성은 멈추지 않고 계속 진행합니다. 미리보기는 늘 **현재 값**과 비교해 보여 줍니다.
- 바뀐 셀은 미리보기에서 지금 값을 가리지 않고 주황 테두리만 두릅니다. 패널에는 "요청 때 값 → 지금 값"과 AI 제안을 함께 보여 줍니다.
- 기본은 건너뛰기입니다. 셀마다 또는 한 번에 덮어쓰기를 고를 수 있고, **지금 값으로 다시 요청**하면 같은 지시를 최신 시트로 다시 보냅니다.
- 삭제도 "빈칸으로 바뀐 것"이라 같은 규칙을 따릅니다. 행·열 삽입이 없어 주소가 밀리는 문제는 없습니다.
- 내가 입력 중이던 값도 적용 직전에 확정되어 같은 규칙으로 판단됩니다.

### 2. 한 사람이 AI 결과를 검토하는 동안 다른 참여자에게 보이는 것

- 그 범위에 검토하는 사람의 색 점선과 "○○ · AI 결과 검토 중"(생성 중이면 "AI 편집 중") 이름표가 보입니다. 참여자 목록에도 같은 상태가 나옵니다.
- **AI의 제안 값은 보이지 않습니다.** 확정되지 않은 값이 실제 데이터처럼 보이면 혼란스러울 것이라고 판단했습니다.
- 기본으로는 해당 구역을 편집하는 것을 막지 않고, 다른 사용자가 AI 편집을 적용/검토 중임을 알리기만 합니다(soft lock). 입력하면 편집칸 위에 "○○님이 AI 결과 검토 중 · 입력한 값은 기본으로 유지돼요"가 뜹니다.
  - 기본을 하드 락으로 두지 않는 이유: 사람의 작업 흐름이 AI 때문에 끊깁니다.
  - 툴바의 **AI 편집 시 셀 잠금**을 활성화하면, AI 편집 결과를 적용하거나 버릴 때까지 요청한 범위(시트 전체 요청이면 시트 전체)를 다른 참여자가 바꿀 수 없습니다(hard lock).
  - 잠긴 셀에서 입력을 시작하거나 지우기·서식을 바꾸면 막히고 "○○님이 AI 편집을 위해 잠근 셀이에요"가 뜹니다. 이름표와 참여자 목록에는 "· 잠금"이 붙습니다.
  - 잠기기 전에 이미 입력하던 값은 입력할 수 있습니다. 입력한 글자를 버리지 않고, 그 셀은 1번 규칙대로 충돌로 표시됩니다.
  - 잠금은 다음 요청부터 적용되고, 요청할 때 정해진 범위는 실행이 끝날 때까지 바뀌지 않습니다.
- 검토하던 탭이 닫히면 Web Locks로 즉시 감지해 표시와 잠금이 사라집니다.

### 3. 두 사람이 겹치는 범위에 동시에 AI 편집을 요청하면

- 보내기 전에 입력칸 위에 "○○님이 이 범위를 AI로 편집 중이에요"가 뜹니다. 그래도 요청은 막지 않습니다.
- 먼저 적용한 쪽의 변경은 나중 쪽에게 1번 규칙대로 충돌로 표시되고, 기본으로 건너뜁니다. 두 AI가 같은 값을 냈다면 충돌이 아닙니다.
- 잠금이 없으니 서로 기다리다 멈추는 일이 없습니다. 거의 동시에 눌러 서로의 표시를 못 본 경우에도 같은 규칙으로 처리되어, 누가 먼저 봤는지에 결과가 좌우되지 않습니다.
- 셀 잠금을 쓰면 예외입니다. 남이 잠근 범위에는 요청할 수 없고, 다른 AI 편집과 겹치는 범위는 잠글 수 없습니다. 그래서 잠긴 범위에는 늘 AI 실행이 하나뿐입니다.

### 한계

- 적용과 거의 같은 순간(탭 간 전달 지연 안)에 다른 탭에서 같은 셀을 고치면, CRDT 규칙에 따라 두 값 중 하나로 모든 탭이 같게 수렴합니다. 이 짧은 틈까지 막으려면 서버가 순서를 정해 주어야 합니다. 셀 잠금도 탭 사이 메시지로 알리므로, 잠금이 전달되기 전의 아주 짧은 순간에 한 입력은 막지 못하고 충돌로 처리됩니다.
- 셀 잠금은 실행 취소·다시 실행은 막지 않습니다. 잠기기 전에 내가 그 셀에 한 편집을 되돌리면 값이 바뀌고, AI 결과에서 충돌로 표시됩니다.
- 검토 중인 제안은 그 탭에만 있습니다. 새로고침하면 사라지고 다시 요청해야 합니다.
